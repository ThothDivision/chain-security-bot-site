01 — Why

“Minted from thin air” keeps happening.

These are real, public incidents and disclosures in the Cosmos ecosystem. Some were exploited, some were caught first. Each one broke an invariant that software could have watched.

02 — How it works

Check the code before it ships. Watch the chain after.

  1. A

    Scan

    csb scan takes a path or git URL. It parses CosmWasm crates and follows each execute path. It flags mint, transfer and admin effects that nothing authorises. It writes SARIF for GitHub code scanning and a Markdown report for humans.

  2. B

    Watch

    csb watch keeps a baseline of what the chain is allowed to do, such as issuance from x/mint inflation. It polls public LCD/RPC endpoints and compares every new reading against that baseline.

  3. C

    Alert

    When an invariant breaks, csb sends the numbers to Discord, Telegram, Slack or any webhook: what changed, by how much, at which height, and what the policy allowed.

03 — Detectors

12 CosmWasm rules today. Solidity through proven open-source engines.

These are heuristic rules that run on the syntax tree, and every finding needs a human to review it. On CosmWasm/cw-plus (87 files), csb reports 0 critical and 0 high findings, plus 4 medium/low unbounded-iteration notes.

05 — Monitoring

Invariants, not dashboards.

An exploit usually shows up somewhere as a number that should not be possible. csb writes each of those down as an invariant and checks it on every block or poll.

  • works today

    Total supply vs issuance

    Uses the x/mint inflation rate or your own ceiling. Catches step jumps and slow drips against the baseline, and ignores lagging nodes.

  • planned · wk 3

    Mints from unexpected authorities

    Watches mint events over CometBFT websockets and compares the minter to an allow-list of modules and accounts.

  • planned · wk 4

    IBC escrow = counterparty supply

    For each channel, escrowed native tokens must equal the voucher supply on the other chain.

  • planned · wk 4

    Account balance ≤ total supply

    Catches wrap-around balances, as in the 2026 Cosmos EVM exploit, where total supply stayed flat.

  • planned · wk 5

    Bridge outflow budgets

    Flags large outflows with no explanation and flows that exceed a rate limit, per route.

  • planned · wk 5

    Code & admin changes

    Watches for contract migrations, admin changes and new code IDs on contracts you care about.

06 — Roadmap

Where the preview goes next.

  1. Now

    CLI csb scan with 12 CosmWasm rules, SARIF + Markdown output and Solidity adapters. csb watch supply with webhook alerts. CI runs the test suite.

  2. Weeks 2–3

    Call graphs that span files and work through traits, cw-multi-test proofs-of-concept for each finding, and a mint-event stream over CometBFT websockets.

  3. Weeks 4–5

    IBC escrow invariants, a check that no account holds more than total supply, bridge budgets and alerts on admin or migration changes.

  4. Weeks 6–8

    A hosted dashboard, per-chain policies, a GitHub App for pull-request scanning and the first design partners.
